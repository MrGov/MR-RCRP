# E20 — 杠杆探测结果：精确瓶颈下降在已记录解上的可改进空间

日期：2026-10-30 · 脚本 `src/mrta_rect_coverage/experiments/e20_headroom_probe.py` · 产物 `outputs/e20_headroom_probe/{headroom.json,REPORT.md}`
git head：见 `headroom.json` 的 `summary.config.git_head`

## 0. 一句话结论

**预注册假设 H-A 被否证**：对 64 条已记录最优解施加"精确瓶颈下降"（把临界机器人上的任务精确搬走 / 跨机器人精确交换，每个候选路线都由完整 8 状态 Route-DP 计价），makespan 的**中位改进是 0.00%**，远低于预注册门槛 0.5%。62.5% 的记录（40/64）**一次改进都没有**——它们已经是该邻域类的精确局部最优。

因此：**"BE-ALNS 作为后处理"这条路不成立**，不能作为创新点。剩下的可用事实是两条，都比原设想窄得多（见 §5）。

## 1. 做了什么

对 E12（48 条 = 4 实例 × 6 方法 × 2 seeds）与 E19（16 条 = 4 实例 × 2 臂 × 2 seeds）的 `best_routes` 逐条施加确定性下降：

- **M1 精确搬运**：临界路线（makespan 承载者）的每个任务 → 每个目标路线的每个插入位，route DP 精确计价；接受判据 `(max, sum)` 字典序严格改进。
- **M2 精确交换**：临界路线每个任务 × 其他路线每个任务，两侧各自枚举全部插入位取最优（仍是精确 route DP）。
- 每趟只针对当前临界路线，改进则重算两条路线代价，直到无改进移动或达到 20 万次计价。

全部 64 条记录 `start_makespan` 与记录值逐条一致（`makespan_mismatch = 0`），总耗时 **100 s**，无一条被时间/计价上限截断（`time_limited = 0`），所以 0 改进是"搜完没有"而不是"没搜完"。

## 3. 为什么我们自己没有空间

现有 ALNS 的两类移动已经隐性覆盖了搬运：

- destroy 把任务摘掉、repair 用贪心插入到任意位置，**等价于一次搬运**；repair 内部本身对每个插入位调用 route DP；
- 已有的 `local_search` 阶段进一步做路线内的改进。

交换则**完全没有**：ALNS 从不把"任务 i 与任务 j 原子互换"作为单一移动，所以"搬一个太轻、搬两个太重"的情形它表达不出来。这正是仅剩的两处有意义改进的来源：

- `Proposed / HV-GEOM / R2_T20_0 / s1`：2405 → 2353（**+2.162%**，纯 3 次交换、0 次搬运）
- `Proposed-E18 / TRAVEL-HIGH / R8_T80_0 / s0`：6621 → 6551（**+1.057%**，13 次搬运 + 1 次交换）

即：**搬运已被覆盖，交换未被覆盖**，且交换的价值集中在模式敏感的 HV-GEOM 与长距离的 TRAVEL-HIGH 上。

## 4. 更不利的一条：对称打磨后我们的名次不改善

如果把**同一把**精确下降施加给所有方法（公平的对称打磨），逐 (实例, seed) 对计算"相对该对最优方法的差距"，越低越好：

| 方法 | 原始差距 | 打磨后差距 |
| --- | ---: | ---: |
| RNSGA | 0.677% | **0.315%** |
| CDABC | 0.913% | 0.533% |
| Proposed (E18) | 1.249% | 1.179% |
| Proposed (E11) | 1.388% | 1.220% |
| MRHDABC | 1.493% | 1.076% |
| SGA-TS | 3.293% | 1.272% |
| B1 | 1.831% | 1.853% |

两个事实必须正视：

1. 在 E12 的这支 4 实例 × 2 seeds 开发集上，**我们不是最好的**——RNSGA 与 CDABC 都比我们好，我们排第三/第四。这与 E19 已记录的负增益（对 CDABC −0.478%、对 RNSGA −0.718%）一致，不是新矛盾。
2. 打磨后我们的相对名次**没有改善**（1.220% → 1.179%），而 RNSGA 从 0.677% 降到 0.315%。也就是说"我们也做精确打磨"并不能追平差距；SGA-TS 的 +1.77% 恰恰说明"打磨"是它与我们的差距，而不是我们与 RNSGA 的差距。

## 5. 对设计的影响（按可信度排序）

1. **撤掉"BE-ALNS 后处理"作为贡献**。中位 0 改进，写进论文只会被审稿人用一句话拆掉。
2. **保留"交换"这一条，但只作为组件**：ALNS 缺的就是原子交换；长期看它应该作为一个**移动类型**进入搜索（在 SA 循环里与 destroy/repair 并列），而不是事后打磨。收益量级 ~1–2%，且只在模式敏感/长距离实例上出现。
3. **"精确嵌套评价"的价值要换论证方式**：它真正解释的是**基线**为什么差（SGA-TS 留下 1.34% 的中位空间，本质是它的解没做精确状态/插入计价），不能用来解释我们比别人强。这条可以写成机制性论证，但必须承认：任何人在基线上加同样的精确打磨，都会吃掉其中一部分。
4. **真正的阻塞不是"还有多少空间"，而是名次**。当前算法在开发集上落后 RNSGA/CDABC。在这个前提下继续堆机制（交换、状态、更多算子）都是在错误的优先级上做功——先搞清楚 RNSGA/CDABC 到底赢在哪里（按实例族、按规模、按预算使用），再决定改什么。
