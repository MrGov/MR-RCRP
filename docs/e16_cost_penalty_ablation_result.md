# E16 成本惩罚固定墙钟对照（S vs S+cost）：结论为**关掉**

- 状态：已完成（2026-10-30），git HEAD `9020311`
- 运行器：`src/mrta_rect_coverage/experiments/e16_cost_penalty_ablation.py`
- 产出：`outputs/e16_cost_penalty_ablation/`（`runs.json` / `pairs.json` / `summary.json` / `REPORT.md`）
- 上游：`docs/task_P1_iteration_cost_penalty.md`（P1 开关实现）、`docs/p2_feedback_design.md` §7b（标定）

---

## 1. 为什么先做这一步

P1 的 `iteration_cost_penalty` 只是**奖励整形**：它改变分段权重更新的分数质量，
从而影响算子被抽中的概率。它不改接受准则、不改算子集合、不改内层 DP。
在把 P2 的反馈结构建在它之上以前，必须先回答一个问题：

> 在一个固定墙钟预算里，让权重感知迭代成本，能不能真的改变最终 makespan？

若不能，它就是一层与机器速度绑定的噪声整形，不该带着进 P2/P3，
更不该写进创新点。

## 2. 设计（预注册）

| 项 | 设定 |
| --- | --- |
| 臂 | `off`（B1 预设）/ `on`（同一预设 + 标定 `t_ref`） |
| 终止 | **固定墙钟预算 8 s**（固定迭代数会让机制按构造失效） |
| 配对 | 每个 (实例, seed) 各跑一次；臂顺序按 (实例序号+seed) 奇偶交替，平衡机器漂移 |
| 规模 | 8 实例（7 个结构族 + BASE 的第二个重复）× 3 seeds = **24 配对 / 48 次运行** |
| 实例 | `data/e10_structural_development/<族>/R4_T40_<r>.txt`，4 机器人 40 任务 |
| `t_ref` | `4.977e-02 s`（e15 标定，见 §4） |
| 统计 | 配对 `delta_rel` 中位数 + 5000 次 bootstrap（seed 20261030）95% CI |

预注册判定规则（看数字之前写死）：

- `KEEP`：中位数 < 0 且 CI 上界 < 0
- `KEEP_WEAK`：中位数 < 0 但 CI 含 0
- `TURN_OFF`：`|中位数| < 0.005` 且 CI 含 0
- `TURN_OFF_HURT`：CI 下界 > 0

## 3. 结果

### 操纵检验（机制确实生效了）

- 开启臂中被折价的迭代占比（24 个配对的中位）：**45.1%**
- 中位迭代数：off `95` / on `90`（`KEEP_WEAK`，CI 极宽，属噪声）
- 说明：机制不是「没跑起来」，而是**跑起来后没有带来性能差异**。

### 主结果

| 指标 | 值 |
| --- | --- |
| 配对 `delta_rel` 中位数（on − off） | **`+0.00248`**（开启臂略**差** 0.25%） |
| 均值 | `-0.00327` |
| bootstrap 95% CI | **`[-0.00844, +0.00865]`** |
| on 更好 / 更差 / 持平 | 10 / 12 / 2 |
| 判定 | **`TURN_OFF`** |

CI 对称地跨 0，胜负几乎五五开，中位数在噪声带内（阈值 0.5%）。

## 4. 一个必须记住的标定教训

第一版 `e15` 用「单次冷缓存 `evaluate_route` 耗时 × κ=8」当参考，
在 `R2_T6_0`（6 任务）上标出 `t_ref = 4.92e-04 s`。但一次完整 ALNS 迭代在
40 任务实例上要 `4.98e-02 s` —— 相差 **约 100 倍**。实测：

- 6 任务实例：1 次迭代 ≈ 50 个 probe 单位
- 40 任务实例：1 次迭代 ≈ **800 个 probe 单位**

原因是迭代成本由 repair（贪心插入 × 大量 DP 调用）与 local search 主导，
不是由一张 DP 表主导。以 probe 为单位标定会让因子变成对**所有**算子一律乘 `~0.1`
的常数 —— 公共缩放不改变算子排序，机制按构造变成空操作。

**已改**：`e15` 现在的标定单位是**一次真实 ALNS 迭代**（7 个结构族各跑 40 步确定性 pilot，
取 `measured_stage_seconds` 池化中位数），`κ=1.0` 的含义是「中位迭代拿满分，
只有明显更贵的迭代被折价」。`probe_units_per_iteration` 仍作为诊断字段写进
`calibration.json`（实测 `800.2`）。

## 5. 决定

1. **成本惩罚不进入 P2/P3。** 代码保留（`iteration_cost_penalty` 默认 `False`，
   测试保留），因为它现在是可复现的负结果，删掉反而丢了证据。
2. **它不作为创新点。** 论文里只能作为「我们也试过成本感知，无收益」的一句话交代，
   不能出现在贡献列表或实验臂里。
3. **P2 的反馈结构不依赖它。** P2 的证据注入走 `feedback_builder`/`prompt_builder`，
   与本开关正交。

## 6. 局限（必须与结论一起引用）

- 这是**范围检查**，不是确认性检验；8 s 墙钟预算随机器负载漂移。
- 24 配对的 CI 宽度约 ±0.85%，只能排除「大于约 1% 的收益」，不能排除更小的收益。
  但即便存在 <1% 的真实收益，它在 MCID=2%（`statistical_analysis_plan.md`）下也不构成结论。
- 折价因子在 45% 的迭代上 <1，但幅度温和（中位迭代因子为 1.0），
  可能是「惩罚太软所以无效」—— 然而更硬的惩罚会变成常数缩放而同样无效（§4），
  这两条一起说明：**在分段权重框架里，迭代成本不是一个能改变算子排序的信号**。
