## 0. 范围

本文回答三个问题：

1. DP 里到底有什么信息是可反馈的（依据 `问题示例描述.pdf` 的模型定义）；
2. 这些信息如何组织成一条链（L1/L2/L3）；
3. 如何在不改动宿主 ALNS 控制器、不改动评价真值的前提下，把它接进演化闭环。

不在本文范围：新算子设计、求解器改造、真实 LLM 调用预算、最终实验结论。

## 1. 问题结构：8 状态与确定性出口

### 1.1 状态定义

任务区域为轴对齐矩形，允许进入/离开的点只有四个角：`LB / LT / RB / RT`。每个任务可独立选择水平扫掠（H）或垂直扫掠（V）。因此**每个任务的配置状态恰好 8 个**：

```
state = (entry_corner ∈ {LB,LT,RB,RT}) × (sweep_mode ∈ {H,V})
```

每个状态的其余量**全部由几何确定，不含自由度**：

| 量 | 公式 |
|---|---|
| 扫掠次数 | `N_i^H = ceil((yT-yB)/δ)`，`N_i^V = ceil((xR-xL)/δ)` |
| 区内行程 | `D_i^H = N_i^H · (xR-xL)`，`D_i^V = N_i^V · (yT-yB)` |
| 处理时间 | `T_i(m) = D_i^m / v + (N_i^m - 1)·τ` |
| 出口顶点 | 由 `(entry, mode, N_i^m 奇偶)` 查表唯一确定 |

出口映射（`N` 偶 = 同侧翻转，`N` 奇 = 对角）：

- H 偶：`LB→LT, RB→RT, LT→LB, RT→RB`
- H 奇：`LB→RT, RB→LT, LT→RB, RT→LB`
- V 偶：`LB→RB, LT→RT, RB→LB, RT→LT`
- V 奇：`LB→RT, LT→RB, RB→LT, RT→LB`

### 1.2 三条恒等式

对一条路线 `r = (i1, i2, ..., ik)`、给定状态 `s_j`：

```
T_cov(r)      = Σ_j T_{i_j}(mode_j)                                  （覆盖时间，与顺序无关）
T_transfer(r) = d(depot, entry_1) + Σ_j d(exit_j, entry_{j+1}) + d(exit_k, depot)
cost(r)       = T_cov(r) + T_transfer(r)
makespan      = max_r cost(r)
```

其中 `d(·,·)` 为曼哈顿距离，`v = 1, δ = 2, τ = 0.5`，depot 在 `(0,0)`。

**关键：转移项只依赖相邻两个任务的 `(exit, entry)`，因此对固定任务序列而言代价函数是「可加的 + 状态马尔可夫的」，DP 精确最优成立。** 这正是 DP 能作为仪器的前提：它不是近似器，它给出的表和最优解一一对应。

### 1.3 数值验证（对 `问题示例描述.pdf` 第 4 页）

| 任务 | w×h | N_H / T_H | N_V / T_V | 奇偶（H/V） |
|---|---|---|---|---|
| 1 | 8×3 | 2 / 16.5 | 4 / 13.5 | 偶 / 偶 |
| 3 | 12×4 | 2 / 24.5 | 6 / 26.5 | 偶 / 偶 |
| 4 | 6×14 | 7 / 45.0 | 3 / 43.0 | 奇 / 奇 |
| 6 | 6×16 | 8 / 51.5 | 3 / 49.0 | 偶 / 奇 |

与 PDF 给出的映射分组一致，模型理解无误。

## 2. 由结构直接推出的五条事实

**F-1｜处理时间与进入顶点无关，只与模式有关。**
`T_i` 只有两个取值 `{T_i^H, T_i^V}`。进入顶点与出口顶点只影响转移项。→ 覆盖时间是任务的**模式属性**，不是路径属性。

**F-2｜覆盖时间与访问顺序完全无关。**
因此：*任何只改变顺序的操作，对覆盖时间零贡献*，其收益上界完全由转移项决定。反过来，*任何改变分配/模式的操作，才会影响覆盖项*。

**F-3｜状态是实例级静态查表。**
给定实例，每个任务的 8 个状态（出口、处理时间、n_sweeps）是常量。因此「状态定义」只需记录 `(task_id, state_id)`，无需在每条解上重复存几何量。记录成本 ≈ 0。

**F-4｜出口是硬约束，不是决策。**
算子若"想"让某任务从 LB 进、从 RT 出，它必须先选对 `(entry, mode)` 并满足奇偶表。这是生成算子最容易写错的地方，也是最值得显式反馈给 LLM 的地方。

**F-5｜奇偶表造成出口映射的跳变。**
`N` 的奇偶决定出口在同侧还是对角。同一任务 H 与 V 的奇偶通常不同（例：任务 6 为 `H 偶 / V 奇`），因此"换个模式"可能同时改变覆盖时间和出口位置，耦合是双向的。

## 3. 代价三通道分解

由 F-1/F-2，`makespan` 的构成可以精确拆成三个通道，互不重叠、可加：

| 通道 | 定义 | 受什么影响 |
|---|---|---|
| **C1 覆盖** | `Σ_i T_i(mode_i)` 按机器人分摊 | 模式选择；任务→机器人的分配 |
| **C2 转移** | 相邻 `(exit, entry)` 曼哈顿距离 + depot 腿 | 顺序；进入顶点；出口（间接） |
| **C3 均衡** | `max_r cost(r) − mean_r cost(r)` | 分配；瓶颈路线结构 |

**这是整个反馈设计的骨架**：任何算子的效果都只能经由这三个通道作用于 makespan，因此可以把"算子好坏"从标量变成**三通道归因向量**。这比 makespan 排名信息密度高，而且不需要任何额外求值——数据在 DP 表里本来就有。

## 4. 四个旁路仪表

全部为只读旁路，不参与求解、不改变接受准则、不改变权重更新。

### I1 · 通道占比

每条路线与全局各给两个数：`cov_share = T_cov / cost`，`transfer_share = 1 - cov_share`。

用途：直接告诉 LLM **该写哪一类算子**。若 `transfer_share` 很小，顺序优化已无空间，应转向分配/模式；反之亦然。

### I2 · 状态链

每任务的 `(entry, mode, exit)` 序列 + 模式切换点 + 首个分叉点。

用途：几何可解释性；识别"模式抖动"（相邻任务反复换 H/V 但收益为负）。

### I3 · 配置松弛度（slack）

定义：把任务 `i` 强制置为次优状态后，**对该任务之后的后缀重新做一次 DP**，得到的最优代价增量。

```
slack(i) = DP_reopt(suffix, state_i := second_best) - DP(suffix, state_i := best)
```

**注意（修正）**：不能用 `V[i][s2] - V[i][s1]` 的层间差近似——下游可以重新优化，层间差会系统性低估松弛度。后缀重优化每次 `O(n·64)`，成本可忽略，但**必须重算**才能得到真实的"改动容忍度"。

用途：`slack ≈ 0` = 刚性锚点（别动）；`slack` 大 = 有富余（可以动）。

### I4 · 算子作用域上界

给定当前解，问："如果你只改这一类，理论上最多还能省多少？"

```
order_gain_bound(r) = T_transfer(r) - MST({depot} ∪ S_r)      （顺序类上界；任何闭合巡游 ≥ MST）
mode_gain_bound(r)  = T_cov(r) - Σ_{i∈S_r} min(T_i^H, T_i^V)   （模式类上界）
balance_gain_bound  = max_r T_cov(r) - (Σ_r T_cov(r)) / R       （分配类上界）
```

三者均为**界**，不是可达值，只用于定向，不作为最优性证明。

用途：这是最"指令式"的一条反馈。例："当前瓶颈路线 `order_gain_bound = 3.2`，而 `balance_gain_bound = 27.5` —— 顺序优化已接近极限，收益在分配。" 这句话能直接把 LLM 的编辑方向拨到正确的一类算子上。

`core/lower_bounds.py` 已有部分下界工具，MST 界需确认是否可复用，否则按上述定义独立计算（`O(n^2 log n)`，`n ≤ 50` 无压力）。

## 5. 数据结构

### 5.1 `StateChainRecord`（每「解 × 路线」一条，L1+L2）

| 字段 | 类型 | 说明 |
|---|---|---|
| `route_id` | int | |
| `task_order` | int[] | 访问序列 |
| `state_ids` | int[] | 每任务的全局 state_id（静态查表，见 F-3） |
| `entry_corners` / `exit_corners` / `modes` | str[] | 由 state_ids 展开，供 LLM 直读 |
| `mode_switches` | {idx, from, to}[] | 模式切换点 |
| `segment_costs` | {task, intra, inter}[] | `intra = T_i`，`inter = 到下一任务的转移` |
| `cov_total` / `transfer_total` / `cost` | float | 三通道量 |
| `slacks` | {task, slack}[] | I3 |

### 5.2 `CounterfactualPair`（L3，父子对比一条）

| 字段 | 说明 |
|---|---|
| `input_signature` | `{partial_solution_hash, removed_tasks, seed}`，三者必须完全一致 |
| `parent_state_chain` / `child_state_chain` | 双方的 `state_ids` 摘要 |
| `task_deltas` | `{task, route_p→c, pos_p→c, state_p→c, entry_p→c, mode_p→c}` |
| `channel_delta` | `{cov, transfer, balance}`（C1/C2/C3 精确增量） |
| `first_divergence` | 状态链首次分叉的任务下标 |
| `verdict` | `better / worse / neutral`（按 `cost`，不按 makespan） |
| `attribution` | 枚举：`bottleneck_relief / bottleneck_worsen / route_overload / mode_thrash / parity_violation / no_effect` |

`attribution` 用**有限枚举**：既能让 LLM 不跑偏，也让后续统计可聚合。

### 5.3 `PerturbationProbe`（L3，敏感性探针一条）

| 字段 | 说明 |
|---|---|
| `probe_type` | `force_alt_state / move_task / swap_adjacent / drop_task` |
| `target` | 探测对象 |
| `delta_cost` / `delta_route` | 精确增量（后缀重优化后） |
| `feasible_break` | 是否导致不可行 |

探针必须使用**独立派生 seed**，禁止复用主 ALNS 的 RNG，否则会污染配对可比性。

### 5.4 `FeedbackPayload`（投影输出）

| 字段 | F0 | F1 | F2 | F2' |
|---|---|---|---|---|
| `quality`（标量/排名） | ✓ | ✓ | ✓ | ✓ |
| `reliability`（四轴 outcome） | ✓ | ✓ | ✓ | ✓ |
| `regime`（实例结构特征） | ✓ | ✓ | ✓ | ✓ |
| `top_weak` | | ✓ | ✓ | ✓ |
| `state_chain_highlights` | | | ✓ | ✓ |
| `scope_bounds`（I4） | | | ✓ | ✓ |
| `counterexamples`（5.2） | | | | ✓ |
| `probes`（5.3） | | | | ✓ |
| `hypotheses`（2–3 条可选方向） | | | | ✓ |

## 6. 采样与预算

记录量 = 候选 × 实例 × seed × 代数，必须设闸：

1. **只记录判决点**：每代最优、每代最差、每个与父代配对的同 seed 运行。中间过程解一律丢弃。
2. **进 prompt 前必须压到 ≤ 5 条 highlight**。完整表落盘供离线分析，不进上下文。
3. **反事实配额**：每候选 ≤ 2 个 `CounterfactualPair` + ≤ 3 个 `PerturbationProbe`，超出按「瓶颈路线优先」裁剪。
4. **探针的 DP 调用要计入预算**：F2' 的求解预算相应扣减，否则赢了也是靠多算。

## 7. 四臂反馈与 F2' 模板

- F0：标量 + 排名（下界）
- F1：+ top/weak（现有多轮基线）
- F2：+ 状态链描述 + 作用域界（"信息更多但仍只是描述"）
- F2'：+ 反事实 + 探针 + 可选方向（**主张所在**）

F2 vs F2' 是最干净的消融：同样的 DP 信息，一个描述、一个反事实 + 指令。

### F2' 文本骨架

```
【你的改动实际发生了什么】
同一输入（partial solution / removed set / seed）下父子行为差异：
- 任务 37：路线 2 第 5 位 → 路线 4 第 1 位；状态 13 (LB,H) → 状态 22 (RT,V)
- 状态链在任务 37 首次分叉，影响其后 6 个任务
- 通道增量：覆盖 +0.0，转移 +11.0，均衡 -8.0
- 判定：route_overload

【为什么】
- 路线 4 为瓶颈路线（cost 152），其平均 slack 仅 0.4
- 路线 2 有 3 个任务 slack > 8（有富余）
- 当前 order_gain_bound=3.2 而 balance_gain_bound=27.5：顺序已接近极限，收益在分配

【可选方向】（非强制）
- 搬运前先检查目标路线是否为当前最紧路线
- 或：对 slack 高的路线做搬出，而非向瓶颈路线搬入
```

## 8. 接入点（三处，全部旁路）

1. **评价包装层旁**：解评价返回后把 DP 回溯指针交给 M1 生成 `StateChainRecord`；失败降级为空记录，不阻断求解。
2. **反馈构造处**：按臂选择 payload 字段子集，走不同模板。
3. **prompt 组装处**：模板插槽，仅 F2' 渲染反事实段与方向段。

M1/M2/M3 的划分：

| 模块 | 职责 | 是否触碰现有代码 |
|---|---|---|
| M1 状态链记录器 | DP 回溯 → L1/L2 摘要 | 否（旁路观察者） |
| M2 反事实探针 | 受控扰动 → L3 增量 | 否（独立调用） |
| M3 反馈投影器 | 按「最反常段落」切片渲染 | 否（反馈构造处的分支） |

## 9. 实验设计要点

- 统计单元 = 独立进化 run；层级 `run → generation → candidate → instance → seed`。
- 等预算：LLM 调用数、候选数、DP 调用数、探针数、求解秒数全部对齐并报告。
- 部署一律跑在常驻 worker 上（否则会重犯 E13 揭示的「把部署开销误读成机制无效」）。
- 主判据：held-out 实例族上的质量/稳定性；`attribution` 分布的跨实例稳定性作为机制证据。
- 反向判据：若 F2' 不显著优于 F2，则说明瓶颈不在信息密度——该结论本身需如实报告。

## 10. 风险与降级

| 风险 | 缓解 |
|---|---|
| prompt 膨胀 | 摘要 ≤ 5 条；完整表只落盘 |
| 探针破坏确定性 | 独立派生 seed；配对输入三元组严格一致 |
| 记录内存 | 只留判决点；状态表实例级缓存 |
| 过拟合 dev 布局 | held-out 检查 `attribution` 分布 |
| LLM 把建议当命令、多样性塌缩 | hypotheses 标注为可选；监控候选源码编辑距离分布 |
| 探针使 F2' 多算 | 预算扣减 + 探针调用计数入账 |

## 11. 实施顺序与验收

1. **M1（只记录不反馈）**：跑现有流程，人工读几张 `StateChainRecord`，验证字段能否解释「为什么贵」。零风险、不污染实验。
2. **M3 的 F2 臂**：描述符版，得到「信息更多但无指令」的对照。
3. **M2 + F2'**：反事实版，跑等预算对照。
4. 中途停止也有产出：一份「MR-RCRP 的 DP 状态链可观测性分析」，可独立成节。

验收检查点：

- CP1：对已知最优解，`T_cov + T_transfer` 与现评价器 makespan 完全一致（数值影子校验）。
- CP2：手工构造的状态链与 PDF 例子的映射一致（任务 1/3/4/6）。
- CP3：同一 `input_signature` 下两次反事实运行结果逐位相同。
- CP4：四个仪表在不改变任何解的情况下可重复计算。

## 12. 与文献的定位

不主张演化机制新颖（生成→评价→反馈→变异→精英沿用现有程序进化范式），主张的是**证据基座**：

| 借鉴 | 借思想 | 替换 |
|---|---|---|
| ReVEL 类行为画像反馈 | 反馈应是行为画像而非标量 | 画像基座：通用性能剖面 → DP 状态链 |
| EoH-S 类启发式集合设计 | 评价对象是集合 | 互补度量：实例性能 → DP 响应 |
| RouteRepair 类失败感知修复 | 反例驱动、定向修补 | 反例来源：失败日志 → 精确 DP 结构反例 |

差异化依据：本问题的出口由 `(entry, mode, 奇偶)` 硬确定（F-4），覆盖与转移解耦（F-1/F-2），因此 DP 表天然提供三通道精确归因与作用域界——这在点目标路由问题里不存在。
