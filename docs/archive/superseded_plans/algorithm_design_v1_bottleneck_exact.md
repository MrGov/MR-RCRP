# 算法设计 v1：从问题结构出发的瓶颈精确搜索（BE-ALNS）

日期：2026-10-30 · 状态：设计稿，未改代码 · 目的：把算法定下来，而不是继续扩实验

本稿刻意**不从既有文档的方法叙事出发**，只从三件事出发：问题本身的结构、我们自己的实测数字、以及"最终测试要赢对比算法"这个目标。

---

## 1. 从问题出发：目标被什么决定

MR-RCRP 的结构特征（不是文献结论，是这个模型的性质）：

- 目标 `M = max_r C_r`，是**最大值**，不是求和。
- 每条路线的代价 = 覆盖（只取决于模式）+ 任务间转移 + 出入 depot 腿；其中**状态（4 进入角 × 2 模式）由 DP 在给定顺序下精确最优选取**，出口角被奇偶表唯一决定。
- 因此外层要决定的只有：**分派 + 顺序**。状态不是自由变量，是内层最优化的结果。

我们自己的实测（e10 21 实例 / v1 dev 84 实例，两次一致）：

| 量 | 数值 | 含义 |
| --- | --- | --- |
| transfer 占比 | 79.4% / 81.8% | makespan 主要由**旅行**决定 |
| coverage 占比 | 16.2% / 14.4% | 处理时间，部分可被模式选择改变 |
| turning 占比 | 4.4% / 3.8% | 可忽略 |
| 负载超出 `B = M − mean` | M 的 11.7% / 12.5% | **max 目标下、可被重新分配吃掉的部分** |
| 有信息的状态位置 | 28.7% | 大多数位置的状态替换是零后悔（几何上等价） |
| `|mode_gap| ≥ 1%·M` 的位置 | 2.9–4.0% | 模式选择整体是小杠杆 |

**结论（这是本设计的出发点）**：既然 `M = mean + B` 且 `B ≈ 12%·M`，那么把 `B` 压下去的直接收益上限就是 ~12% —— 比我们过去所有算子层面的改进（±0.1–0.2%）**大两个数量级**。而状态层最多值 3%，且只在 4% 的位置上有信息。

所以杠杆排序是：**L1 瓶颈再平衡 ≫ L2 路线内/跨路线顺序 ≫ L3 状态与模式**。任何把主要算力放在 L3 的设计，都注定只能拿到噪声级的收益 —— 这正是过去几个月方法线的错位之处。

## 2. 为什么"换一个更好的算子"无法兑现 L1

`M` 是 max，而 ALNS 的常规 destroy/repair：

- destroy 按几何/随机/相关性选任务，**不区分哪个机器人是瓶颈**；
- repair 用精确边际插入代价，但插入目标按"总增量最小"选，**不是按"最大路线能否下降"选**；
- SA 接受准则比较 `M`，但邻域本身对瓶颈无偏置；
- 分段权重把 4 个算子混合采样，单个算子的质量被 25% 的暴露率稀释。

于是即使某个算子"更好"，它也在解一个**代理目标**（总代价/随机路线），而不是绑定约束。这解释了 E19 的 +0.077% 中位差：**干预点没对准约束**，不是算子不够好。

## 3. 算法规格：BE-ALNS

保留：精确 Route-DP 内层评价、ALNS 骨架、SA 接受、冻结与哈希纪律。
新增：**三个精确护栏**，把算力直接压在瓶颈上。

### 3.1 记法

- 路线 `T_r`（有序任务列表），精确代价 `C_r = DP(T_r)`（对 8 状态做分层 DP，`O(|T_r|·64)`）。
- `M = max_r C_r`，`mean`，`B = M − mean`；瓶颈路线 `r* = argmax C_r`。
- 逐位置状态后悔 `Δ_j = min_{s≠s*} Q_j(s) − C_r*`（`Q_j` 由一次前向 + 一次后向得到，已有实现 `core/state_chain_report.py`）。

### 3.2 M1 — 瓶颈精确搬运（relocate）

对瓶颈路线的每个任务 `i`、每个目标路线 `r'≠r*`、每个插入位置 `p`：用 DP 精确计算 `C_{r'}(i@p)` 与 `C_{r*}(−i)`，按 `(M', Σ C)` 字典序取最优。

- 精确，不近似：每个候选的代价都是"对该顺序下的状态赋值再最优化"后的真实值 —— 这是本问题特有的可负担性：一次路线 DP 实测 0.44 ms（40 任务），
  `n=100, R=8` 时单趟约 `|T_r*|·(R−1)·|T_r'| ≈ 13·7·13 ≈ 1180` 对，约 0.25 s。
- 单调：只接受使 `M` 严格下降（或 `M` 持平且 `Σ C` 下降）的移动，因此不会破坏 SA 的可行性，也不会掩盖退步。

### 3.3 M2 — 跨路线精确交换（swap）

`i` 在瓶颈路线、`j` 在其他路线，交换位置后两条路线各重算一次 DP；评估同 M1。
解决"单任务搬不动但成对可换"的情形（离散负载下很常见：搬一个太轻、搬两个太重）。

### 3.4 M3 — 状态刚性驱动的 ruin

移除集合不再是几何聚类，而是按**DP 才能算出的信号**：

- `rigid = { i : Δ_i 小 }` —— 该任务的状态选择被邻居锁死（无论换哪个进入角/模式都亏），说明它被**顺序**钉在坏位置，是搬迁的最佳切入点；
- `free = { i : Δ_i = 0 且 tied_state_count ≥ 4 }` —— 状态完全自由，搬迁的"状态惩罚"为零，也是好目标；
- `bottleneck`：瓶颈路线上的任务优先。

三者拼成移除池，再交给 repair（保留现有精确边际插入）。这一步是 L1 与 L3 的交汇：**用状态层的精确信息去改进顺序层的邻域选择**。

### 3.5 局部最优证书

当 M1/M2 在当前解上连续一轮无改进时，记录一个**可验证的证书**：在该邻域类（单点搬运 + 成对交换，且每个候选含内层状态最优化）下不存在改进移动。种群类方法（CDABC/RNSGA）无法给出这种陈述。

### 3.6 LLM 的位置（次级贡献，不是主线）

LLM 在给定**逐迭代在线 DP 特征**（`Δ_j` 分布、`mode_gap`、瓶颈路线集合、`B/M`、transfer share）下生成 **ruin/recreate 策略**（M3 的选题规则与 repair 的排序偏好）。
必须有反装饰对照：**同样特征、手工规则**（M3 的固定阈值版本）作为一臂，LLM 臂只有在同特征同预算下显著更好时才算贡献。

## 4. 贡献与"不够新"的自我批判

### 可以主张的三层

1. **精确嵌套评价作为搜索机器**（不是打分器）：外层候选（分派/顺序）的评价本身是一个内层最优化（8 状态 DP）。因此"精确评估一个邻域"在本问题里是被内层最优化定义过的，而不是简单的代价重算。用它把 max 目标的**瓶颈邻域做到可实现的最优性证书**。
2. **状态刚性 `Δ_j` 作为搬迁判据**：把"哪个任务值得动"从几何代理量（距离、相关性）换成"该任务的状态选择被邻域锁死的程度"。这个量只有精确 DP 能给出，标量/日志/种群适应度都伪造不出来。
3. **（次级）DP 证据驱动的策略生成**，带同特征手工策略的反装饰对照。

### 会被怎么质疑，以及我的应对

- **"relocate + swap 就是标准局部搜索"** → 承认；差异必须落在"候选评价 = 内层最优化"与"证书"上，不能靠说邻域新。**这条需要在写作前做一次定向文献核查**（带"服务朝向/状态选择"的路径问题里，是否存在"每个候选内嵌一次最优化"的精确局部搜索）。我目前**没有**核实过，标为 UNVERIFIED。
- **"CDABC/RNSGA 早就做过瓶颈/精英策略"** → 它们用近似适应度与采样；我们的差异是精确与可证书。但需要在同一预算下用数据说话，不能只靠论断。
- **"如果 `B` 本来就不可压缩，你的杠杆是空的"** → 这是最可能致命的质疑，而且**可以先用现有数据 30 分钟回答**（见 §6）。
- **"LLM 是装饰"** → 用反装饰对照正面回答，而不是回避。

## 6. 第一步：30 分钟的杠杆探测（不改算法代码）

在写任何 `alns_solver.py` 改动前，用**已有产物**回答 H-A：

- 输入：`outputs/e12_literature_baselines/runs/**/best_routes`（6 方法 × 4 实例 × 2 seeds）与 E19 的两臂记录；
- 操作：对每条记录施加 M1+M2 精确下降至局部最优；
- 输出：每方法 `M_initial → M_descent`、下降百分比、消耗的路线 DP 次数与秒数；
- 判读：
  - 若**所有方法**都下降 ≥0.5%，说明这批解普遍留有瓶颈余量 → 杠杆真实，且现有方法都没吃到 → 直接支持 H-B；
  - 若只有我们的 ALNS 下降多、CDABC/RNSGA 几乎不动，说明它们已经在瓶颈上做得更好 → 要重新设计邻域（或承认差距）；
  - 若全部不降，`B` 不可压缩 → **放弃路线 2，回到"证据基座"这个较弱但诚实的主张**。

这是唯一能在写代码前决定算法命运的实验，成本约 30 分钟、零代码侵入。
